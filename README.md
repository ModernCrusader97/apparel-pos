# 의류매장 POS — 재고 / 고객 / 포인트 / 직원권한 / 결제증빙 / 일일마감

파이썬만 있으면 됩니다. **설치할 패키지 없음** (표준 라이브러리만 사용).

## 실행

```
python pos.py --seed
```

http://localhost:8000 → 첫 실행 때 콘솔에 찍히는 **점주 계정 `admin`**으로 로그인.
비밀번호는 `POS_ADMIN_PW` 환경변수로 정하고, 안 주면 `admin1234`입니다 (로그인 후 바로 바꾸세요).

매장 다른 단말(태블릿·다른 PC)에서도 쓰려면 서버 역할 PC에서:

```
python pos.py --host 0.0.0.0 --port 8000
```

다른 기기에서 `http://서버PC의IP:8000` 으로 접속.

## 의류 — 색상/사이즈 SKU

같은 옷의 색상·사이즈 하나하나가 **별개의 SKU(상품 행)** 입니다. 재고·판매·바코드가 전부 그 단위로 돕니다.

재고 탭 → **＋ 색상/사이즈 일괄등록** 에 품번·색상·사이즈를 쉼표로 넣으면 조합을 한 번에 깝니다.

```
품번 TS-2601 / 베이직 반팔티 / 블랙,화이트,네이비 / S,M,L,XL  →  12개 SKU
```

- 바코드는 `품번-색상-사이즈` 로 자동 생성됩니다. 행택 바코드가 따로 있으면 나중에 수정하세요.
- 이미 있는 조합은 건너뜁니다 (색상 추가 입고 때 같은 품번으로 다시 돌리면 됨).
- 중간에 하나라도 실패하면 **하나도 만들어지지 않습니다** (한 트랜잭션).
- 재고 탭 기본 화면이 **품번별 색상×사이즈 매트릭스**입니다. 숫자를 누르면 그 SKU의 입출고 창이 열립니다.
- 사이즈 정렬은 XS·S·M·L·XL·2XL·3XL·FREE 순이고, 숫자 사이즈(26/28/30/32)는 숫자 순입니다.

교환은 따로 기능을 두지 않았습니다. **판매취소 후 재판매**로 처리하세요 — 취소가 매니저 권한이라
교환할 때마다 매니저가 승인하게 되고, 재고·포인트·카드승인이 전부 정상 경로로 되돌아갑니다.

## 발주 제안

재고 탭 → 보기 **발주 제안**. 판매속도로 "뭘 몇 장 더 시켜야 하는지" 뽑습니다.

```
일평균 판매 = 기간 판매수량 ÷ 실제 판매 가능일수
목표 재고   = 일평균 × (입고 소요일 + 커버 일수)
권장 발주   = max(목표 재고, 안전재고) − 현재고
```

분석 기간 / 입고 소요일 / 커버 일수는 화면에서 바로 바꿉니다 (기본 30일 / 7일 / 14일치).
거래처 리드타임과 재입고 주기에 맞춰 조정하세요 — 이 세 숫자가 발주량을 좌우합니다.

**'실제 판매 가능일수'로 나누는 게 핵심입니다.** 2주 전 들어온 신상을 30일로 나누면
판매속도가 절반으로 깎여 잘 나가는 신상이 재발주에서 빠집니다. 의류에서 제일 아픈 실수라,
취급 시작일(첫 입고일)부터만 셉니다.

| 상태 | 뜻 | 할 일 |
|---|---|---|
| **품절** | 팔리는데 재고 0 | 제일 급함. 맨 위에 옵니다 |
| **보충** | 커버 기간을 못 버팀 | 권장 수량만큼 발주 |
| **안팔림** | 2주 넘게 한 장도 안 나감 | 발주 금지. 할인·반품 등 정리 대상 |
| **충분** | 재고가 목표 이상 | 그냥 둠 |

- 취소된 판매는 판매속도에 반영되지 않습니다.
- **소진예상** = 현재고 ÷ 일평균. 며칠 뒤 품절인지 보여줍니다.
- 상단에 총 발주 수량·**예상 매입액**과, 안 팔리는 재고에 **묶인 돈**을 같이 띄웁니다.
- **발주서 CSV**를 내려받아 거래처에 그대로 보내면 됩니다 (합계 줄 포함).

재고가 0인 동안은 팔고 싶어도 못 팔아 판매속도가 실제보다 낮게 잡힙니다.
품절이 잦았던 품목은 권장 수량이 보수적으로 나오니, 품절 표시된 건 수량을 올려 잡으세요.

## 일일 마감 (시재 정산)

정산 탭에서 그날 **서랍에 있어야 할 현금**과 실제로 센 금액을 맞춥니다.

```
예상 현금 = 개시 시재금 + 그날 들어온 현금 − 그날 나간 현금(환불)
```

- **들어온 현금** = 그날 *판매된* 현금 건 전부. 나중에 취소되더라도 그날 서랍엔 들어왔습니다.
- **나간 현금** = 그날 *취소된* 현금 건 전부. 판매일이 언제든 환불은 오늘 서랍에서 나갑니다.
- 당일 팔고 당일 취소하면 양쪽에 잡혀 저절로 상쇄되고, **어제 판 걸 오늘 환불하면 오늘 서랍에서만** 빠집니다.
- 개시 시재금은 **전날 마감 때 센 금액**을 이어받습니다 (첫 마감은 설정의 기본 시재금).
- 차액이 나면 메모를 남기고 마감합니다. 다시 세서 재마감할 수 있고, 두 번 다 감사 로그에 남습니다.
- 마감하면 그 시점 DB가 자동 백업됩니다.

## 자동 백업

```
backup/pos-20261012.db
```

- **하루 1회** 자동 백업 + 마감할 때마다 1회. 기본 **14일 보관**, 오래된 건 자동 삭제.
- 파일 복사가 아니라 SQLite 온라인 백업을 씁니다 — **영업 중에 돌려도 깨지지 않습니다**.
- 설정 탭(점주)에서 즉시 백업과 파일 목록을 볼 수 있습니다.
- 경로·보관일수는 `POS_BACKUP_DIR`, `POS_BACKUP_KEEP` 환경변수로 바꿉니다.
- 백업본은 그냥 SQLite 파일입니다. 복구는 `pos.db` 자리에 덮어쓰고 재시작하면 끝입니다.

> 백업 폴더가 그 PC 안에만 있으면 PC가 고장났을 때 같이 날아갑니다.
> `POS_BACKUP_DIR` 을 USB나 클라우드 동기화 폴더(구글 드라이브 등)로 잡아두세요.

|---|---|---|---|
| 판매, 입고, 고객등록 | O | O | O |
| 상품 등록·가격변경, 폐기·실사조정 | | O | O |
| **판매취소**, **포인트 수기조정**, 정산·증빙, **일일 마감**, **발주 제안** | | O | O |

돈·재고가 움직이는 민감 작업(판매취소, 포인트조정, 재고폐기, 가격변경, 일일마감, 계정변경, 설정변경, 백업)은
**누가 언제 무엇을** 했는지 감사 로그에 남고 지울 수 없습니다. 횡령·실수 추적용입니다.

## 카드단말(VAN) 연동

카드 승인은 VAN사 계약 + 매장 PC에 설치되는 결제모듈이 있어야 합니다.
이 프로그램은 **그 모듈을 호출하는 쪽**입니다.

```
POS_VAN_URL=http://127.0.0.1:9900/pay python pos.py
```

- 설정하면: 결제 시 단말로 자동 승인, 판매취소 시 자동 승인취소, 현금영수증도 단말 경유 발급.
- 미설정이면: 승인번호를 수기로 입력하는 모드로 동작합니다 (단말 전표 번호를 그대로 입력).

VAN사마다 전문 규격이 다릅니다. 계약 후 받는 연동규격서대로 [pos.py](pos.py) 의 **`van()` 함수 하나**만
고치면 됩니다 (payload 키 이름과 응답 파싱). 기대 응답 형식:

```json
{"ok": true, "approval_no": "12345678", "card_name": "신한", "message": ""}
```

**카드 승인이 난 뒤 DB 기록이 실패하면 승인을 자동으로 취소합니다.** 돈만 빠져나가는 상황을 막기 위한 것이고,
승인취소까지 실패한 경우에만 단말 전표로 수기 취소해야 합니다 (그 사실도 로그에 남습니다).

## 현금영수증 / 세금계산서

- **현금영수증**: 국세청 직접 연동은 불가하고 실무상 VAN사가 같이 처리합니다.
  결제 화면에서 용도(소득공제/지출증빙)와 식별번호를 넣으면 VAN 경유로 발급하고,
  미연동이면 "대기" 상태로 남겨 증빙 탭에서 승인번호를 수기로 채웁니다.
  판매를 취소하면 현금영수증도 취소 상태가 됩니다.
- **세금계산서**: 발행 자체는 홈택스/팝빌 등의 몫입니다.
  고객에 사업자등록번호를 등록해 두면 증빙 탭에서 **월별 공급가액·세액 집계**가 잡히고,
  **발행용 CSV**를 내려받아 홈택스/팝빌에 올리면 됩니다.
  판매가를 부가세 포함으로 보고 공급가액 = 합계 ÷ 1.1 로 계산합니다.

## 태블릿 / 데스크톱 겸용

버튼 크기는 화면 크기가 아니라 **입력 장치**로 정합니다 (`@media (pointer: coarse)`).
태블릿·터치 모니터에서는 자동으로 모든 조작 요소가 **48px 이상**으로 커지고,
마우스 쓰는 데스크톱은 지금의 조밀한 밀도를 그대로 씁니다. 설정은 필요 없습니다.

자동 감지가 안 맞는 기기(터치 겸용 올인원 등)를 위해 **설정 → 화면**에서
`자동 / 항상 크게 / 항상 작게` 를 고를 수 있습니다. 이 값은 **그 기기에만** 저장되므로
계산대 PC는 작게, 매장 태블릿은 크게 쓸 수 있습니다.

영수증·정산 인쇄는 큰버튼 모드와 무관하게 항상 조밀하게 출력됩니다.

**폰(560px 미만)** 에서는 배치가 한 번 더 바뀝니다. 탭 7개가 헤더에서 세 줄로 접혀
화면의 20%를 먹던 것을, 탭이 제 줄을 통째로 쓰고 넘치면 옆으로 미는 방식으로 바꿔
13%로 줄였습니다. 상품·장바구니 줄은 품명이 한 줄을 통째로 쓰고 가격·재고·버튼이
아랫줄에 모입니다. 점주가 외부에서 매출·재고를 확인하는 용도로 쓸 만합니다.
다만 주 계산대는 태블릿이나 데스크톱을 쓰세요 — 폰은 한 화면에 들어오는 상품 수가 적습니다.

## 영수증 프린터 (선택)

감열 영수증 프린터가 **네트워크(LAN)** 모델이면 서버가 직접 출력합니다.

```
POS_PRINTER=192.168.0.50:9100 python pos.py
```

- 결제하면 자동 출력되고, 영수증 창의 "프린터로 출력" 버튼으로 재출력합니다.
- **미설정이면 지금처럼 브라우저 인쇄**를 씁니다. 동작이 바뀌지 않습니다.
- **USB 프린터는 안 됩니다.** 브라우저도 서버도 USB 장치에 직접 말할 수 없습니다.
  USB 모델이면 브라우저 인쇄를 쓰세요.
- 출력이 실패해도 판매는 그대로이고, 실패는 감사 로그에 남습니다.

기종마다 코드페이지와 용지 폭이 달라 **실물로 맞춰야 합니다**:

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `POS_PRINTER_CP` | `cp949` | 한글 코드페이지. 글자가 깨지면 `euc-kr` 등으로 바꿔 보세요 |
| `POS_PRINTER_WIDTH` | `42` | 한 줄 글자 수. 80mm=42, 58mm=32 |
| `POS_PRINTER_TIMEOUT` | `5` | 연결 대기 초 |

## 데이터

`pos.db` (SQLite) 한 파일. 백업은 위의 자동 백업이 알아서 합니다.

## 중요한 동작 규칙

- 가격은 **항상 서버 DB 값**을 씁니다 (브라우저가 보낸 금액은 무시).
- 재고 차감 + 포인트 적립/사용 + 판매 기록은 **하나의 트랜잭션**. 중간에 실패하면 전부 취소됩니다.
- 카드 승인 같은 네트워크 호출은 트랜잭션 **밖**에서 합니다 (DB 락을 수십 초 잡지 않도록).
- 재고·포인트는 **음수가 될 수 없습니다**.
- 포인트로 결제한 금액은 적립 대상에서 제외합니다 (포인트 무한증식 방지).
- 판매 취소 시 재고·포인트·카드승인이 되돌려집니다. 적립 포인트를 이미 써버린 고객은
  자동 취소가 막히고 수기조정을 요구합니다.
- 상품 삭제는 숨김 처리이며 과거 판매 이력은 보존됩니다.
- 사업자등록번호는 국세청 체크섬으로 검증합니다.
